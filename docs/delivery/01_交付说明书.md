# D121 多从机工业场景监控系统 交付说明书

版本 2026-10-25

## 项目概览

本项目面向多从机工业场景的设备监控。本次以星火传感从站和龙芯系统指标从站为例，由 D121 汇聚数据，在触摸屏上显示、记录和回放，并将摘要与关键事件上传到云端。

截至 2026 年 10 月 25 日，双站 Modbus、本地记录与回放、设备 TLS、关键事件补传和手机移动网络访问已有验收依据。当前约定范围的开发与短时验收已收口；长期观测按用户要求暂停。

![项目概览](assets/architecture.png)

| 组成 | 职责 |
| --- | --- |
| D121BBV 主站 | RT-Thread 与 LVGL；双站轮询、数据有效性、事件、TF 记录与本地回放 |
| 星火 STM32F407 地址 1 | AHT21 温湿度、ICM-42688-P 六轴数据、有效性与采样缓存 |
| 龙芯 LS2K0300 地址 2 | LoongOS 系统 CPU、内存、负载、运行时间与通信统计 |
| NodeMCU ESP8266 | 独立 AT 网络模块，校时并验证服务器证书后建立加密 MQTT 链路 |
| 云后台与小程序 | 持续接收与 MySQL 归档、登录配对、趋势、历史、事件详情 |

阅读顺序：先看硬件与数据约定，再查版本及证据。现场演示请另用《拍摄与发言指南》。文中验收数值是指定日期的检查点，不是实时状态或性能上限。

## 硬件与接口

### 总线与调试口

| 接口 | 当前配置 |
| --- | --- |
| RS485 总线 | 单主站半双工；Modbus RTU 115200 / 8N2；星火地址 1、龙芯地址 2 |
| D121 数据串口 | UART3，PB10 / PB11，沿用已验证的收发器及方向控制接线 |
| 龙芯收发器 | MAX3485 模块 3.3V；UART1；EN 对应 TIM2_CH2 / GPIO88 |
| D121 调试口 | 现有电脑 COM6，115200 / 8N1；端口号换电脑后应重新确认 |
| 星火调试口 | 现有电脑 COM5，115200 / 8N1；与 RS485 的 8N2 配置不同 |
| NodeMCU USB | 现有电脑 COM10；最终日常 AT 命令经 D7 / D8，不走 USB 桥原 RX / TX |

### 接线核对原则

三板保留已经通过实机通信的 RS485 A/B 和共地连接。RS485 模块上的 TX/RX 命名可能不同，不能只按其他品牌模块的丝印推断方向。本材料没有重新设计全部板卡原理图，底层引脚以随附接口表和原工程硬件记录为准。

NodeMCU 使用独立 USB 供电。它与 D121 连接两根信号线和一根 GND；两板 3.3V 电源不连接。D121 主板和星火保持原有供电。

### 屏幕与存储

本地界面为 480 × 272 深灰配色，总览、趋势、黑匣子和设置四页。TF 为正常记录介质，NOR 与 RAM 提供降级路径；RAM 内容断电丢失。正常启停会产生新采集会话，日志按既有容量与轮转策略保留。

龙芯调试串口此前为 COM7，但当前演示不依赖打开它。不要将调试串口当作 USB-RS485 适配器，也不要用系统软件重启作为演示步骤。

## NodeMCU 最终接线位置

下图是按常见 30 引脚 NodeMCU 及官方引脚顺序绘制的位置示意。按板上 D7、D8、GND 丝印核对；USB 朝向和外观相似不能代替丝印确认。

![NodeMCU 最终接线位置](assets/wiring.png)

| D121 | NodeMCU | 信号方向 |
| --- | --- | --- |
| PA2 / TX | D7 / GPIO13 / RX | D121 发送，ESP8266 接收 |
| PA3 / RX | D8 / GPIO15 / TX | ESP8266 发送，D121 接收 |
| GND | GND | 共地 |

最终 ESP-AT 参数：TX=GPIO15、RX=GPIO13，115200；关闭 CTS/RTS 和额外控制引脚。原 GPIO1/3 保留 ROM 烧录用途。改变固件与工厂参数时，必须同步核对 AT 引脚，不能把台架 USB 测试参数当作最终参数。

## 数据与可靠性设计

### 采集和显示的含义

主站星火记录目标约 10 Hz，龙芯系统指标目标约 1 Hz；云端约每秒保存摘要。星火 IMU 使用独立采样缓存，Modbus 查询复制缓存，避免在应答路径重新探测传感器。现场频率与新鲜度以实际计数和样本年龄判断。

通信在线、数据新鲜和传感器有效是三个条件。温湿度超过约 3 秒失效，IMU 缓存超过约 200 ms 失效；有效的 0 ℃、0 %RH 或全零轴数据仍允许。无效数据不能画成真实的零值。

手机“振动峰值”取约一秒内已有采样中 abs(加速度幅值 - 1g) 的最大值，单位 g。它不是 RMS、频谱或静止/倾斜/冲击/跌落分类。云端摘要也不是 TF 的完整六轴原始波形。

### 关键事件的保存与补传

- 通信中断/恢复、结温越限/恢复、振动越限/恢复进入事件记录；龙芯另有数据更新和采集程序状态事件。
- 关键事件连同一份事前有效摘要先写入 NOR 队列；云后台事务提交成功后返回应用确认，设备收到相关确认才移出队列。
- 原 boot、collection 和事件身份用于去重与时间解释。丢失确认可能导致重发，数据库身份键负责去重。MQTT 传输仍为 QoS0。
- 队列最多 256 个待确认事件；满队列、持久化失败、事件缺口均有计数。普通实时摘要不会补出全部断网曲线。

### TLS 验证

设备使用 Bemfa 9503 端口，固定服务器认证模式与 CA 索引 0，设置服务器域名和 SNI。定制 ESP-AT 启用证书日期验证并自动 SNTP 校时，未得到可靠日期时连接可能需要等待。后台到 MQTT 的传输配置本轮未调整，不能把设备端 TLS 表述为所有链路均已加密。

## 启动检查与维护

### 演示前的状态检查

沿用当前硬件连接与热点，先检查本地双站和 TF，再检查 TLS 与云端。电脑端默认调试口 COM6 / COM5，可在辅助脚本参数中修改；同一串口只由一个工具占用。

```powershell
Set-Location 'D:\codex相关项目\D121交付与演示材料'
.\tools\demo.ps1 -Action Check
```

正常基线：bbstat 两站 online/stale 与 env_valid/imu_valid 合理，written 持续增长，新增 dropped/write_errors 为 0；cloud stat 显示 online=1、tls=1、auth_verified=1、queued=0；apphealth 显示 tripped=0、bb_ok=1。

### 维护与恢复入口

- D121：使用原工程 work/scripts/flash/d12x_flash.ps1 与 OS/rodata 更新包，保留 SPL、NOR 数据与 TF；不以完整出厂镜像代替日常更新。
- 星火：使用 ST-Link / STM32CubeProgrammer，核对 STM32F407 与目标地址；已有验收烧录成功，不需要为拍摄再次烧录。
- 龙芯：已安装的 loongson-slave2 服务默认自动运行；部署包由原 install.sh 校验并保留旧程序，不把普通系统 reboot 作为恢复办法。
- ESP8266：按内包 manifest 分段地址烧录，DIO / 40MHz / 2MB 分区布局、26MHz 晶振；物理芯片为 4MiB，空 NVS 需重新配置。

原 ESP AT 1.7.4 完整 4MiB 备份已两遍分段比较并匹配设备整片 MD5，位于原工程私有 backups 目录；SHA256 已记录，含配置而不随公开包分发。尚未实际完整回刷，不能称回退演练通过。数据库隔离恢复通过也不等于已替换生产库或执行集群回档。
