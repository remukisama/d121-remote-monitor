## 拍摄安排与准备

推荐录制约 5 分钟的主视频，按本指南 6 个镜头分段拍摄；若投递平台仅允许短视频，另用 90 秒介绍稿。实际时长取决于讲话速度、界面读取和联网恢复，先做一次不录制的彩排。

| 准备项 | 完成标准 |
| --- | --- |
| 设备 | 三板与 NodeMCU 保持最终接线；热点持续开启；TF 正常；不为拍摄重新烧录 |
| 画面 | 横屏 1080p，固定机位，屏幕无明显反光；先拍全景，再补屏幕与手机录屏 |
| 手机 | 打开当前可用小程序，确认登录、双站更新时间、事件与详情；热点和移动网络保持可用 |
| 电脑 | 解压材料，关闭占用 COM6/COM5 的串口终端；命令窗口只显示状态，不打开私有配置 |
| 声音 | 安静环境，短句慢讲；每次操作前后停 1–2 秒，给画面留出观察时间 |
| 证据 | 先记录 Check 基线；本轮事件以当场新增为准，不预填历史事件 ID 或读数 |

### 拍摄顺序

实物与架构 → 正常数据 → 本地和云端历史 → 单站异常 → 上传暂停与补传 → 恢复后的结果。演示讲解页用于介绍架构与逻辑，实机视频仍要使用真实屏幕和实际事件。

提词器可以离线打开，按镜头切换，也可显示完整稿；支持字号、滚动速度和播放暂停。提词窗口放在镜头附近，手机录屏时不必把提词器录进去。

## 分镜与口播 上半场

### 00:00–00:30 项目与实物

镜头：全景拍到三块主从板、NodeMCU 和 D121 屏幕；用指示笔按主站、星火、龙芯、网络模块顺序指认。

操作：保持热点、供电和原有接线；用正常在线画面开场。

口播：大家好，下面演示这套基于 D121 的双节点设备监控终端。它把两台从站的数据汇总到本地屏幕，同时记录历史并上传云端。我会先展示正常采集，再演示单站异常和上传恢复后的事件补传。

观察：实物与系统组成一一对应；无需展示密码、云控制台或烧录过程。

### 00:30–01:15 正常采集与数据

镜头：近景拍 D121 总览，切换星火和龙芯，再录手机总览和趋势。

操作：展示温湿度、振动峰值、CPU、内存和运行时间。可轻轻晃动传感板观察振动变化，停下后看恢复。

口播：星火从站提供温湿度和六轴数据，龙芯从站提供 CPU、内存和运行时间。主站通过同一条 RS485 总线轮询，协议是 Modbus RTU。这里可以切换两台从站；数据是否在线、是否新鲜、传感器是否有效分别判断。手机上的振动值是一秒内采样点的峰值指标。

观察：两站在线，更新时间推进；晃动对应振动数值变化，不将其称为动作识别。

### 01:15–02:00 历史与本地回放

镜头：拍 D121 黑匣子事件列表和一条可用回放，再拍手机历史事件及详情。

操作：选择已有事件并等待读取完成，再切换节点或退出；有缺失窗口时如实展示。

口播：除了当前读数，主站会把数据和事件记录到 TF 卡。这里可以回看事件附近的历史，手机端也能查看云端保存的事件和事前读数。本地原始记录与云端每秒摘要的采样密度不同，缺失的数据会保留为空，不会补画成实际测量。

观察：事件、时间来源、曲线与节点对应；不把旧读数说成当前状态。

## 分镜与口播 下半场

### 02:00–02:45 单站异常隔离

操作：运行 StarFault，软件停止星火应答 3 秒后自动恢复；观察星火离线/恢复、龙芯继续更新。

口播：现在用软件停止星火的应答，模拟单台从站通信中断。星火出现离线事件时，龙芯仍继续采集，本地记录任务也保持运行。恢复星火应答后，数据重新有效，系统保留中断和恢复事件，便于后续回看。

观察：星火离线与恢复均可见，龙芯更新继续；不要剪去故障与恢复之间的关键画面。

### 02:45–04:15 暂停上传与可靠补传

操作：运行 NetworkFault：上传暂停 30 秒，期间停止并恢复星火应答，显示排队事件；随后自动重连并等待队列清空。

口播：接下来采用软件暂停上传，做一次受控断网模拟。本地采集继续运行；暂停期间，再产生一组星火通信中断和恢复事件，可以看到关键事件进入队列。上传恢复后，设备把事件及事前摘要送到后台，后台写入数据库并返回应用确认，设备才移出这些记录。这里关注队列从有到零，以及云端能否读到对应事件。MQTT 本身仍使用 QoS0，可靠补传由应用层队列、确认和数据库去重共同完成。

观察：offline 时 queued 增加，恢复后 online=1、tls=1、auth_verified=1、queued=0；手机能打开本轮事件。

### 04:15–05:00 结果与边界

操作：运行 Check，确认双站、TF 和网络均恢复；结尾展示正常状态。时间不足时保留这一步。

口播：最后，两台从站已经恢复在线，本地记录继续，上传队列也已清空。设备端 TLS 已检查 CA、服务器域名和证书有效期，手机移动网络下的登录、实时数据、历史和详情也已验证。当前版本完成了从采集、记录到异常补传的链路。长期观测仍待后续进行，精细动作分类和完整离线波形上云还没有实现。以上就是本次演示。

观察：最终状态与发言一致；恢复失败时停止录制并保留日志，不宣称通过。

## 可复制的演示命令卡

在材料根目录打开 PowerShell。若解压到其他位置，请替换示例的 Set-Location 路径。脚本默认只读 Check；故障动作必须显式选择。串口号变化时传入 -MasterPort 和 -StarPort。下面的故障步骤没有在材料生成时自动执行。

```powershell
Set-Location 'D:\codex相关项目\D121交付与演示材料'
# 拍前状态
.\tools\demo.ps1 -Action Check
# 单站中断 3 秒 再恢复
.\tools\demo.ps1 -Action StarFault
# 暂停上传 30 秒 期间产生星火事件
.\tools\demo.ps1 -Action NetworkFault
# 拍后状态
.\tools\demo.ps1 -Action Check
```

| 动作 | 预期现象 |
| --- | --- |
| Check | 两站在线、TF 正常、TLS online、queued=0、看门狗未触发 |
| StarFault | 软件停止星火 3 秒，龙芯继续；finally 尝试恢复星火应答 |
| NetworkFault | 软件暂停上传 30 秒，期间产生并显示事件；最多约 75 秒等 TLS 在线及队列清空 |
| 手动恢复星火 | 若操作被强制关闭，先确认端口空闲，再执行下方恢复命令 |

```powershell
.\tools\board_cmd.ps1 -Port COM5 -Commands 'rs485_slave start 1'
.\tools\demo.ps1 -Action Check
```

辅助脚本是本次新整理的拍摄工具，仅做语法和预览检查；底层命令和对应受控故障模式有既有实机验收。尚未把这份新脚本本身作为已完成实机回归来宣传。现场如失败，停止录制、保留日志，再根据状态排查。

### 约 90 秒项目介绍

大家好，下面介绍这套基于 D121 的双节点设备监控终端。它通过 Modbus RTU 连接两台从站：星火板采集温湿度和六轴数据，龙芯板提供 CPU、内存和运行时间等系统指标。

主站在触摸屏上显示数据，并把采集结果和事件记录到 TF 卡，支持历史回放。数据摘要与关键事件通过 ESP8266 加密上传，在微信小程序中可以查看实时状态、趋势和事件详情。

这次演示重点是异常前后的记录：单台从站停止应答时，另一台仍继续采集；上传暂停期间，新产生的关键事件进入本地队列，网络恢复后补传，并在云端保存确认后移出队列。

目前双站通信、本地回放、TLS、事件补传和手机移动网络访问已经完成验证。长期观测还没有做，完整离线波形上云和精细动作分类也不在当前版本范围。

## 常见追问与回答

### 为什么选择两种从站

“星火提供环境与惯性传感数据，龙芯提供 Linux 系统指标。两种数据通过同一个 Modbus 总线汇聚，主要验证多节点接入、不同数据模型和单站异常隔离。”

### 断网时能保留什么

“本地 TF 继续记录，关键事件和事前有效摘要进入 NOR 队列；网络恢复后补传。云端不会自动得到全部断网原始波形，队列也有容量和错误边界。”

### MQTT QoS0 为什么仍说可靠补传

“可靠性来自应用层。设备保留未确认记录，云端数据库提交后才确认，未确认就重发，数据库按身份去重。它不等于 MQTT QoS1，也不承诺任意故障零损失。”

### 怎么证明 TLS 不是仅仅连上

“实际模块测试了正确 CA 和域名能连，错误 CA、错误域名以及过期证书拒绝；主站最终连接还检查 auth_verified 状态。测试记录和固件版本随交付包保留。”

### 还有什么没完成

“长期观测按当前安排暂缓，精细动作分类、完整离线原始波形上云和主动通知没有实现。龙芯系统普通软件重启还有驱动问题，演示使用正常运行与从站任务恢复。”

### 是否工业级或完全自主开发

“这是当前开发板上的验证项目，没有做工业电气或环境认证。开发使用开源 SDK 和 AI 辅助，我会按实际参与程度和证据说明，不把辅助生成的代码说成全部个人独立实现。”

## 拍摄异常处理与交片检查

| 现场现象 | 处理与口径 |
| --- | --- |
| 节点无效或没更新 | 先检查实际连接、供电及数据有效性；保持真实状态，恢复后再拍，不用历史数值代替 |
| 没有拍到单站离线 | 可能错过短窗口；保留电脑日志后重新彩排，不把恢复后的在线画面标成离线 |
| 云端尚未显示中断 | 后台约 15 秒无新摘要才判断中断，轮询和显示也有延迟；暂停 30 秒并耐心观察 |
| 队列一直未清空 | 确认热点可用和 TLS 在线，检查确认/持久化计数；停止结论性口播并保留日志 |
| 历史回放窗口不完整 | 轮转、采集开始时间和记录空缺都可能影响窗口，展示实际范围并说明 |
| 串口无法打开 | 关闭另一串口工具，确认端口归属；不打开 NodeMCU USB 作为最终 AT 口 |

### 拍完再检查

- 最终双站在线、TF written 增长、queued=0、TLS 认证通过，故障动作已恢复。
- 手机能打开本轮事件及事前读数；不要固定使用验收报告中的旧事件 ID。
- 视频包含真实故障发生、恢复及补传结果；等待可适当加速并标注倍速。
- 画面和日志不露出 Wi-Fi 密码、AppSecret、配对码、私有配置或用户数据库。
- 字幕使用“软件暂停上传模拟”“关键事件及事前摘要补传”“应用层确认”等准确说法。
