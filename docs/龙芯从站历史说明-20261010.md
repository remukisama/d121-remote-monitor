# 龙芯久久派系统指标从站

2026-10-20 更新：默认协议已切换为 Modbus RTU 115200/8N2；旧 AA55 仅由 `--legacy` 显式启用。龙芯已部署 1.1.0-modbus，主站与星火也已烧录；独立 MinimalModbus 跨真实 RS485 总线读取两站、LED 控制、异常检查和持续采集通过，MQTT 与积压补传已恢复。最新接口见[Modbus 寄存器表](../docs/Modbus寄存器表V1.md)，构建、独立工具测试与部署证据见[迁移记录](evidence/modbus-acceptance.md)。以下 AA55 的协议与验收说明保留为旧版本历史。

这是现有D121工程的龙芯侧组件。硬件为用户已有久久派WiFi核心板/LS2K0300，当前LoongOS v0.1、Linux4.19.190+、LoongArch64。默认从站地址2，每秒采样一次；主站查询才发送。没有主动推送或同时担任主站。

## 已实现

- 真实系统开机运行时间、当前进程运行时间、CPU忙碌百分比、内存总量/可用量、1分钟负载和通信统计。
- 独立采集线程、原子快照、字段有效位与样本年龄；CPU首次样本、读取失败和过期都有明确处理。
- AA55自定义协议，01兼容查询、03二进制回显、04系统指标、05身份。最大64字节载荷，显式小端编码；定义见[协议表](../firmware/loongson-slave2/PROTOCOL.md)。
- GPIO88手动半双工方向控制；原子申请初始低电平。写入支持部分写与100ms截止时间，等待软件发送队列和硬件TEMT都清空再释放EN，不使用可能无限等待的tcdrain。
- 分片/连续帧、AA重叠、CRC、结束标记、载荷长度及100ms残帧失效检查。广播、其他地址和ACK不应答。
- 进程互斥与UART独占、正常退出恢复串口并置EN低；systemd自动启动、失败重启、进展看门狗和退出后再次置EN低。
- `/run/loongson-slave2/status.json`每秒原子更新；在RAM中保存，不持续写TF。

温湿度、IMU和实体LED没有接入本从站。兼容查询中的传感占位值有效位为0，不能解读为真实测量。主站当前`mbq query 2`仍只解码旧查询，完整系统指标需主站接入04；这次没有更改主站固件或界面。

## 部署与维护

程序已在实机安装并启用，正常情况下不需再次安装。后续将包传到板上临时目录，解压并执行`sh install.sh`即可更新；安装先检查哈希并备份现有文件，服务启动失败会尽可能还原上版。通过调试串口传输也可行，COM7不是USB-RS485数据适配器。

```sh
systemctl status loongson-slave2 --no-pager
cat /run/loongson-slave2/status.json
journalctl -u loongson-slave2 -n 30 --no-pager
systemctl restart loongson-slave2
systemctl stop loongson-slave2
/usr/local/sbin/loongson-slave2 --snapshot
```

默认服务每秒采样，10秒systemd看门狗；只有主循环存活且采样进展未超过3个采样周期才续看门狗。进程异常退出后等待2秒重启。`ExecStopPost --release-en`覆盖SIGKILL/看门狗异常退出后的EN清理；硬件供电中断时的电平仍取决于模块电路，不作软件保证。

`--snapshot`只采系统指标，不打开UART/GPIO。手动测试可用`--duration 10`，但先停止服务，否则独占检查会拒绝第二个进程。地址可设置2..247；特意拒绝地址1，避免与现有星火冲突。采样周期可设置200..60000ms；若改服务周期，应同步使WatchdogSec大于采样失效窗口。默认1秒已验证。

## 当前LoongOS重启问题

直接`systemctl reboot`在本板实测触发ES8323音频驱动内核空指针崩溃，调用栈为`es8323_i2c_shutdown → snd_soc_component_write`。WSL同版驱动关机回调无条件使用全局`es8323_codec`；实机没有注册声卡，符合未初始化组件指针的情况。

曾测试重启前临时解绑ES8323：音频回调已绕过，但随后在AIC8800 WiFi SDIO移除函数`aicbsp_sdio_remove`再次发生内核崩溃。两次崩溃均已保留日志，并由用户手动重新上电恢复；冷启动后从站均能自动运行。

`/usr/local/sbin/loongson-slave2-reboot`现已禁用，只打印原因并退出2，避免旧指令再次触发失败实验。没有部署强制重启、自动解绑WiFi或修改内核。当前系统普通软件重启尚不可作为可靠功能承诺；维护时先正常停止从站并同步文件，再进行计划的物理复位。实际驱动修复需另行对运行内核与厂商源码核对、构建和验收。
